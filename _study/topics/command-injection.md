## 핵심 개념
- Command Injection은 애플리케이션이 사용자 입력을 OS 명령어 생성 과정에 안전하게 분리하지 않고 사용하여, 공격자가 명령 구조를 조작하고 서버 권한으로 운영체제 명령을 실행하게 만드는 공격이다.
- 일반적으로 별도 수식 없이 Command Injection이라고 하면 OS Command Injection을 의미한다.
- SQL Injection, XSS, Prompt Injection과 공통적으로 데이터여야 할 입력이 실행 의미를 가진 코드·명령으로 해석되는 Injection 계열 취약점이다.

## 공격 조건 및 원리
1. 애플리케이션이 사용자 입력을 OS 명령어 생성에 사용한다.
2. 입력값과 명령어가 문자열 수준에서 결합되거나 Shell 해석에 노출된다.
3. 공격자는 명령 구분자나 추가 명령을 삽입해 원래 의도와 다른 명령을 실행시킨다.
4. OS Shell 또는 명령 인터프리터가 변조된 명령을 웹 애플리케이션의 실행 권한으로 수행한다.

## 공격 피해
- 서버 내 파일·설정·프로세스 접근 및 변경
- 기밀성·무결성·가용성 침해
- 애플리케이션 계정 권한 범위 내 임의 명령 실행
- 추가 침해나 내부망 이동의 발판으로 악용 가능

## 대응 방안
- 가능하면 OS 명령 호출 자체를 피하고 동일 기능을 제공하는 안전한 라이브러리/API 사용
- Shell 문자열 조합 대신 명령과 사용자 입력을 인자(argument) 단위로 분리해 실행
- 사용자 입력을 Allowlist 기반으로 검증
- 애플리케이션 실행 계정에 최소 권한 원칙 적용
- 필요 시 컨테이너·샌드박스 등으로 실행 범위 격리
- 명령 실행 결과의 불필요한 외부 노출 제한

## 유사 개념과 비교
- SQL Injection: 사용자 입력이 SQL 코드로 해석되어 DBMS에서 실행
- XSS: 사용자 입력이 HTML/JavaScript 코드로 해석되어 브라우저에서 실행
- Command Injection: 사용자 입력이 OS 명령어 일부로 해석되어 Shell/OS에서 실행
- Prompt Injection: 사용자 입력이 LLM의 지시사항으로 해석되는 별도 유형의 Injection
