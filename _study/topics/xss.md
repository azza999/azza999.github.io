## 핵심 개념
- XSS(Cross-Site Scripting)는 공격자가 삽입한 악성 스크립트가 피해자의 브라우저에서 신뢰된 웹사이트의 컨텍스트로 실행되도록 만드는 공격이다.
- 사용자 입력이 단순 데이터로 처리되지 않고 HTML/JavaScript 코드로 해석될 때 발생한다.
- 쿠키·세션정보 탈취, DOM 변조, 사용자 권한을 이용한 요청 전송, 피싱 화면 삽입 등으로 이어질 수 있다.

## 주요 유형
- Stored XSS: 악성 스크립트가 게시글·댓글 등 서버 측 저장소에 저장되고, 다른 사용자가 해당 페이지를 조회할 때 실행
- Reflected XSS: 요청 파라미터 등에 포함된 악성 입력이 서버 응답에 그대로 반사되어 실행
- DOM-based XSS: 클라이언트 측 JavaScript가 신뢰할 수 없는 값을 DOM에 위험하게 삽입하면서 발생

## 공격 과정
1. 공격자가 웹 애플리케이션의 취약한 입력 지점에 악성 스크립트를 삽입한다.
2. 애플리케이션이 해당 값을 안전하게 인코딩하지 않고 페이지에 포함한다.
3. 피해자가 페이지에 접근하면 브라우저가 공격자의 입력을 코드로 해석한다.
4. 악성 JavaScript가 피해자 브라우저에서 실행되어 정보 탈취·DOM 조작·비인가 요청 등을 수행한다.

## 대응 방안
- 출력 컨텍스트에 맞는 Output Encoding / Escaping 적용
- 신뢰할 수 없는 값을 innerHTML 등에 직접 삽입하지 않고 textContent 등 안전한 DOM API 사용
- 입력값 검증 및 허용 목록 적용
- CSP(Content Security Policy)로 실행 가능한 스크립트 출처 제한
- 세션 쿠키에 HttpOnly를 적용하여 JavaScript의 쿠키 직접 접근 제한

## 유사 공격과 비교
- SQL Injection: 사용자 입력이 SQL 코드로 해석되어 DBMS에서 실행
- XSS: 사용자 입력이 HTML/JavaScript 코드로 해석되어 피해자 브라우저에서 실행
- CSRF: 피해자 브라우저가 인증정보를 포함한 요청을 사용자의 의도와 무관하게 전송하도록 유도
- SSRF: 서버가 공격자를 대신해 내부·외부 자원으로 요청을 전송
