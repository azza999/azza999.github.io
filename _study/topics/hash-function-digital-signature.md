## 핵심 개념
- 해시 함수(Hash Function)는 임의 길이의 입력을 고정 길이의 해시값(Message Digest)으로 변환하는 일방향 함수다.
- 입력값이 조금만 변경되어도 출력값이 크게 달라지는 눈사태 효과(Avalanche Effect)를 가진다.
- 해시 함수는 비밀번호 보호, 데이터 무결성 검증, 파일 검증, 전자서명 등에 활용된다.

## 안전한 해시 함수의 조건
- 제1 역상 저항성(Preimage Resistance): 특정 해시값이 주어졌을 때 이를 생성하는 원문을 찾기 어려워야 함
- 제2 역상 저항성(Second Preimage Resistance): 특정 원문이 주어졌을 때 동일한 해시값을 갖는 다른 원문을 찾기 어려워야 함
- 충돌 저항성(Collision Resistance): 동일한 해시값을 갖는 서로 다른 두 입력을 찾기 어려워야 함

## 활용
### 비밀번호 저장
- 일반 해시 함수에 Salt만 적용하는 것보다 Argon2, bcrypt, PBKDF2 등 Password Hashing/KDF를 사용하는 것이 적절함
- Salt는 동일 비밀번호의 동일 해시값 생성을 방지하고 사전 계산 공격을 어렵게 함
- 느린 Password Hashing/KDF는 무차별 대입 공격의 계산 비용을 증가시킴

### 데이터 무결성
- 단순 해시는 데이터 변경 여부 확인에 사용할 수 있음
- 공격자에 의한 변조까지 방지하려면 HMAC(Hash-based Message Authentication Code) 또는 전자서명과 결합해야 함

## 전자서명에서의 역할
1. 송신자는 원문에 해시 함수를 적용해 메시지 다이제스트를 생성
2. 메시지 다이제스트에 개인키 기반 전자서명 알고리즘을 적용해 서명값 생성
3. 수신자는 수신 원문을 다시 해시
4. 송신자의 공개키로 전자서명을 검증해 무결성·송신자 인증·부인방지를 확인

전자서명에서 해시를 먼저 사용하는 이유는 대용량 원문 전체를 직접 처리하는 것보다 고정 길이의 다이제스트에 서명하는 것이 효율적이고, 원문 변경 여부를 명확하게 검출할 수 있기 때문이다.
