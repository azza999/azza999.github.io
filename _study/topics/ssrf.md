## 핵심 개념
SSRF(Server-Side Request Forgery)는 취약한 서버가 공격자의 입력을 신뢰하여, 서버가 가진 네트워크 위치와 신뢰 관계를 이용해 내부 API, 사설망 자원, 클라우드 메타데이터 서비스 또는 외부 사이트 등에 요청을 보내도록 만드는 공격이다.

## 공격 과정
1. 공격자는 취약한 서버의 URL 입력값이나 요청 대상 주소를 조작한다.
2. 서버는 공격자가 지정한 주소로 서버 측 요청을 전송한다.
3. 외부에서 직접 접근할 수 없는 내부 주소, 사설 IP 대역, 관리 API, 클라우드 메타데이터 서비스 등에 접근이 이루어질 수 있다.
4. 해당 요청의 응답이나 결과가 공격자에게 노출되거나, 내부 기능이 비인가 상태로 호출될 수 있다.

## 공격 피해
- 서버 내부 API 및 관리 인터페이스 노출
- 사설 IP 대역과 내부망 서비스 접근
- 클라우드 메타데이터의 자격 증명·민감정보 노출
- 서버를 경유한 외부 시스템 요청 및 내부 기능 오용

## 대응 방안
- 서버가 요청할 수 있는 목적지를 Allowlist 기반으로 제한
- 127.0.0.1, 사설 IP, Link-Local 등 내부·특수 주소 대역 차단
- DNS 해석 후 실제 목적지 IP를 검증하고 우회·Redirect를 제한
- 서버의 불필요한 아웃바운드 네트워크 접근을 방화벽·프록시 등으로 통제
- 응답 내용을 사용자에게 그대로 노출하지 않고 필요한 정보만 반환

## 평가 기록
- 2026-10-04: 40/60점
- 최초 독립 답변에서 서버가 공격자를 대신해 내부 API나 외부 사이트로 요청을 보낸다는 핵심 원리를 정확히 설명함.
- 공격 피해와 입력값 검증, 응답 노출 제한 등 기본 대응도 제시함.
- 다만 내부망, Loopback, 사설 IP, 클라우드 메타데이터 등 대표 공격 대상과 Allowlist·아웃바운드 제어 등의 구체적 대응이 최초 답변에서 부족했음.
- 후속 질문에서 내부 주소·사설 IP·클라우드 메타데이터가 서버의 네트워크 신뢰를 악용해 노출될 수 있다는 점을 스스로 설명하여 단순 누락으로 판단함.
- 본 평가는 채팅 기반 내용 숙련도 평가이며 제한시간 내 수기 답안 작성 능력까지 검증한 것은 아님.
