## 핵심 개념
- SQL Injection은 공격자가 사용자 입력을 통해 SQL 구문 구조를 조작하여 데이터 조회, 변경, 삭제 등 비인가 동작을 유도하는 공격이다.
- 취약한 애플리케이션이 입력값을 검증하거나 분리하지 않고 SQL 문자열에 직접 결합할 때 발생한다.
- 기밀성 침해(데이터 열람)와 무결성 침해(데이터 변경·삭제)가 대표적 영향이다.

## 공격 과정
1. 공격자가 취약한 입력 지점에 조작된 Payload를 전송
2. 웹 애플리케이션이 사용자 입력을 SQL문에 직접 결합
3. 변조된 SQL문이 DBMS에서 실행
4. 조회 결과 노출 또는 데이터 변경·삭제 등 비인가 동작 발생

## 대응 방안
- Prepared Statement / Parameterized Query를 사용하여 SQL 구조와 사용자 입력값을 분리
- 입력값 검증 및 허용 목록 기반 검증 적용
- DB 계정에 최소 권한 원칙 적용
- 오류 메시지 및 DB 실행 결과의 과도한 외부 노출 방지

## Prepared Statement 보완 학습
- Prepared Statement는 SQL문의 구조와 사용자 입력값을 분리하고 입력값을 파라미터로 바인딩하는 방식이다.
- 사용자 입력에 따옴표, 주석 기호, SQL 토큰 등이 포함되어도 쿼리 구조를 변경하는 SQL 구문이 아니라 데이터 값으로 처리되도록 한다.
- DBMS가 이를 지원하며 애플리케이션은 DB 드라이버/API를 통해 사용한다.
