## 핵심 개념
- 서버리스 컴퓨팅: 클라우드 제공자가 서버의 프로비저닝·운영·확장을 관리하여 개발자가 인프라보다 애플리케이션 로직에 집중하도록 하는 컴퓨팅 모델.
- 서버가 존재하지 않는 것이 아니라 서버 운영 책임을 추상화하는 방식.

## 특징
- 이벤트 기반 실행: HTTP 요청·파일 업로드·메시지 등 이벤트로 함수 실행.
- 자동 확장: 요청량에 맞춰 실행 인스턴스 확대·축소.
- 사용량 기반 과금: 호출·실행 시간·자원 사용량 등 기준.
- 운영 부담 감소: 서버 프로비저닝과 실행 환경 관리 부담 완화.

## 유형
- FaaS: 개발자가 작성한 함수를 이벤트에 따라 실행하는 서비스. 예: AWS Lambda.
- BaaS: 인증·데이터베이스·스토리지 등 미리 구현된 백엔드 기능을 API·SDK로 이용하는 서비스.

## 구성 및 처리 흐름
1. 클라이언트(Web·Mobile·IoT) 요청.
2. API Gateway가 요청 수신·라우팅.
3. FaaS 함수가 인증·서비스·관리 등 비즈니스 로직 처리.
4. DB·서버·파일 저장소와 연동해 결과 반환.
- 위 흐름은 대표적인 API 기반 예시이며 모든 서버리스 시스템이 API Gateway를 필수로 사용하는 것은 아님.

## 단점과 대응
| 단점 | 내용 | 대응 |
|---|---|---|
| 콜드 스타트 | 비활성 실행 환경 초기화 시 지연 | 사전 준비 인스턴스·초기화 최적화 |
| 벤더 종속성 | 클라우드 고유 API·이벤트 방식 의존 | 표준 API·종속 코드 분리 |
| 실행·자원 제약 | 실행 시간·메모리·동시성 등 한도 | 작업 분할·비동기 처리 |
| 디버깅 복잡성 | 분산 함수·서비스 장애 추적 어려움 | 중앙 로깅·분산 추적 |
| 비용 예측 | 요청 급증 및 호출 연쇄 시 과금 증가 | 사용량 모니터링·예산 알림 |

## 구현 예시: S3 이미지 자동 리사이징
1. 사용자가 S3에 원본 이미지를 업로드.
2. S3 ObjectCreated 이벤트로 Lambda 실행.
3. Lambda(Python handler)가 이미지를 읽고 크기를 변경.
4. 변환 결과를 S3 별도 경로에 저장한 뒤 실행 종료.
