학습 순서와 복습법

먼저 이해하기

“안정적으로 운영한다”는 말은 사람마다 기준이 다르다. SLA는 어느 서비스를 언제 어떻게 재고, 어떤 수준을 지키며, 미달하면 어떻게 할지 정한 약속이다.

답안에 남길 핵심

정의: SLA(Service Level Agreement)는 제공자와 고객이 서비스 범위·수준 목표·측정 및 보고 방법·역할과 책임·미달 시 조치를 합의한 문서다.

회상 단서: 범위 · 지표 · 목표 · 측정 · 보고 · 책임·보상

개념도

읽는 법: SLO는 목표치, SLA는 목표뿐 아니라 측정 방법과 책임·미달 조치를 포함한 합의다.

손으로 그리기: 고객·제공자 → 가운데 SLA → 아래 측정·판단·조치.

개념도 참고: ITPE 지식관리 · SLA. 확인: 2026-11-22.
핵심 관계만 남긴 학습용 재구성. 원본 이미지를 전재하지 않음.

약속의 구성

항목 예시
대상·범위 주문 서비스, 지원 시간, 적용 사용자
지표·목표 가용성·응답시간·복구시간
측정 규칙 관측 위치·기간·제외 시간·집계 방식
역할·보고 양측 책임, 보고서, 이의 처리
미달 조치 원인 분석·개선·합의한 서비스 크레딧

SLA는 합의, SLM은 관리 활동, SoW는 수행 업무 범위를 기술한 문서다. 계약에 포함되는 방식은 상황에 따라 다르다.

셀프테스트 보완 · 구성 절차와 영역별 측정

2교시형 3은 SLA 일반 정의만으로 답이 끝나지 않는다. 전자상거래 운영 전환이라는 조건에 맞춰 구성요소·수립 절차·영역별 지표와 측정방법을 연결한다.

수립 흐름 예시: 핵심 거래·서비스 범위 식별 → 현 수준과 업무 요구 분석 → 지표·목표·측정 규칙 합의 → 책임·보고·미달 조치 확정 → 운영 측정·보고 → 정기 검토·개선.

영역 지표 예시 측정 방법·해석
HW 서버·스토리지 장애시간, 복구 소요시간 장비 상태·장애/복구 이벤트·작업 이력을 결합한다. 장비 생존이 주문 성공을 보장하지 않는다.
SW 주문 API 성공률, 응답시간 백분위, 배포 후 오류율 APM·서버 로그·합성 거래로 관찰한다. 성공 요청의 정의, 분모, 관측 기간과 타임아웃 처리 규칙을 합의한다.
NW 왕복 지연, 패킷 손실률, 구간 가용성 다지점 능동 탐지와 네트워크 관제로 측정한다. 관측 위치·통신구간·표본 주기를 명시한다.
고객 거래 로그인→주문→결제의 완료율·처리시간 실제 사용자 지표와 합성 거래를 함께 본다. 외부 결제·인증 의존성의 책임과 제외 조건도 확인한다.

수치는 계약 조건과 현 수준에 맞춰 합의한다. 임의의 가용률·위약금을 모든 서비스의 의무 기준처럼 쓰지 않는다. 측정 시계·데이터 보존·중복 장애·계획 작업 처리 규칙을 맞춰야 양측 보고가 비교 가능하다.

관련: SoW·SLA·SLM · 공공 SLA. 측정 관점 참고: Google SRE · Implementing SLOs. 표의 지표는 전자상거래 조건에 맞춘 개인 학습용 예시다.

가리고 설명하기

본문을 위로 올려 가린 뒤, 말하거나 빈 종이에 적는다. 정답을 읽기 전에 답한다.

  1. 가용성 99.9%만 쓰면 충분할까?
  2. SLO와 SLA는 어떻게 다른가?
내 답과 비교할 기준

1. 기간·대상·측정 위치·제외 조건·미달 조치까지 있어야 해석 차이를 줄인다.

2. SLO는 목표치, SLA는 목표 외에 고객과의 책임·측정·조치 합의를 포함한다.

상황에 적용하기

공급자는 서버 가동률 100%, 고객은 주문 성공률 97%라고 보고한다. 무엇을 고칠까?

풀이와 판단 근거

서버 생존과 고객 거래 성공은 다른 지표다. 고객 경험에 맞는 지표와 관측 위치·집계 방식을 합의해야 한다.

헷갈리지 않기

가용성·처리량·응답시간은 다르다. 응답시간도 평균과 백분위의 차이를 고려한다. SoW·비즈니스 케이스·제품 백로그를 완전한 동의어로 외우지 않는다.
